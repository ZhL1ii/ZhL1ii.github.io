## 初始思路

```go
func maxSlidingWindow(nums []int, k int) []int {
	res := []int{}

	// 计算第一个窗口最大值
	maxVal := nums[0]
	for i := 1; i < k; i++ {
		maxVal = max(maxVal, nums[i])
	}
	res = append(res, maxVal)

	// right 表示新进入窗口的元素
	for right := k; right < len(nums); right++ {
		out := nums[right-k]
		in := nums[right]

		// 最大值离开，并且新元素无法接替，只能重新遍历窗口
		if out == maxVal && in < maxVal {
			maxVal = nums[right-k+1]
			for i := right - k + 2; i <= right; i++ {
				maxVal = max(maxVal, nums[i])
			}
		} else {
			maxVal = max(maxVal, in)
		}

		res = append(res, maxVal)
	}

	return res
}
```

这个思路虽然仅在最大值滑出窗口时遍历窗口找最大值，但如果遇到**降序排列好**的数组样例，每次窗口滑动的时候，最大值都会滑出窗口，此时这段代码的复杂度仍是O(nk)，并没有本质效率提升。当数组的元素过大时，就会超时。

## 优化方法

现在假设窗口为：

```
[9 8 7]
```

现在只保存了 maxNums = 9

 `9` 离开以后，窗口变为：

```
[8 7 6]
```

这时不知道谁最大，所以需要重新扫描。

那如果我们之前保存的是类似于以下的结构：

```
9
8
7
```

`9` 走了：

```
8
7
```

马上就知道：

```
8 是最大值
```

而 `6` 进来后：

```
8
7
6
```

最大值还是：

```
8
```

下一轮：`8` 走了，就能马上知道：`7` 最大。

所以，不能只记录当前的最大值，还需要记录一些窗口滑动后可能成为最大值的元素。

## 推导所需数据结构

按上面的思路，假设当前窗口**最大值候选元素**为：

```
[8, 7, 6]
```

现在一个 `10` 进来了：

```
[8, 7, 6, 10]
```

因为 10 比前面的数值都大，且晚于前面数字离开窗口，所以前面的 8、7、6 就不可能成为最大值了，那可以把 8、7、6 全部删去，只留下 10。

再来看一个例子：

当前：

```
[9, 7, 5]
```

新来一个 `6`：

```
[9, 7, 5, 6]
```

6 > 5，且6 离开窗口的时间晚于 5 ，所以 5 可以删去，但是 9、7 仍然需要留下。

总结这个需要保存的序列的特点：

9 > 7 > 6，那如果再进来一个 8 ，那么按上面的推导方法，序列就应该变为`9 8`。

> 总而言之，我们维护一个从大到小排列的候选序列，当有新的候选元素进入时，就需要将比新元素小的元素删去。当需要有元素离开时，就直接将候选序列最前面的元素删除即可。

所以现在需要一个满足以下条件的结构：

左边： 可以删除元素、可以读取最大值 

右边： 可以不断删除那些比新元素小的候选元素、可以加入新元素

所以我们需要的是一种**两端都能操作的队列**。这个数据结构叫 `Deque` 即双端队列 (Double Ended Queue)，用这个数据结构就能维护一个上面那种**单调队列**。

## 代码实现

### 模拟双端队列

Golang 中，没有现成的双端队列库，为了简便，可以用切片操作来模拟这样的双端队列。

假设初始队列为：

```go
queue := []int{1, 3, 5}
```

从右边加入元素

```go
queue = append(queue, 7)
```

变成：

```
1 3 5 7
```

看最右边的元素：

```
queue[len(queue)-1]
```

删除最右边的元素

```
queue = queue[:len(queue)-1]
```

例如：

```
1 3 5 7
```

变：

```
1 3 5
```

看最左边

```
queue[0]
```

删除最左边

可以：

```
queue = queue[1:]
```

例如：

```
1 3 5
```

变：

```
3 5
```

所以对于这题：

```go
// 左边看     
queue[0]
// 左边删     
queue = queue[1:]
// 右边看     
queue[len(queue)-1]
// 右边删     
queue = queue[:len(queue)-1]
// 右边加
queue = append(queue, x)
```

### 队列中应存下标

**现在考虑队列里存什么**，由于我们不仅需要知道候选的数字是多少，而且还需要知道这个数有没有滑出窗口。

例如：

```
nums = [1, 3, -1, -3, 5]
        0  1   2   3  4
```

假设：

```
queue = [1, 2]
```

这代表：

```
下标：   1   2
值：     3  -1
```

所以真正比较值的时候：

```
nums[queue[0]]
```

得到：

```
3
```

而：

```
nums[queue[len(queue)-1]]
```

得到队尾候选的值。

同时，如果当前窗口左边界为 left

那么只需要判断：queue[0] < left

就能够知道队首元素是不是已经离开了当前窗口。

例如：

```
当前窗口下标：

2 ~ 4

left = 2
```

如果：

```
queue[0] = 1
```

说明这个候选元素已经在窗口左边：

```
1 < 2
```

所以应该删除。

这类算法有个非常常见的技巧：

> **队列里保存下标，真正需要值的时候再通过** `nums[index]` **获取。**

因为下标同时携带了两类信息：

```
nums[index] → 元素的值
index       → 元素的位置
```

这样既可以比较元素大小，又可以判断元素是否已经离开窗口。

### 完整代码

```go
func maxSlidingWindow(nums []int, k int) []int {
	res := []int{}
	queue := []int{}

	for right := range nums {
		left := right - k + 1

		// 去除已经滑出窗口的下标
		if len(queue) > 0 && queue[0] < left {
			queue = queue[1:]
		}

		// 维护单调队列，从右边开始不断去除比新元素小的数
		for len(queue) > 0 &&
			nums[queue[len(queue)-1]] < nums[right] {
			queue = queue[:len(queue)-1]
		}

		// 当前元素下标入队
		queue = append(queue, right)

		// 形成窗口后，记录最大值
		if right >= k-1 {
			res = append(res, nums[queue[0]])
		}
	}

	return res
}

```

整个循环中主要做四件事：

```
1. 根据 right 计算当前窗口左边界 left

2. 删除已经离开窗口的队首元素

3. 从队尾不断删除比 nums[right] 小的候选元素

4. 将 right 加入队列
```

最终，因为队列始终保持：

```
nums[queue[0]]
>=
nums[queue[1]]
>=
nums[queue[2]]
...
```

所以：

```
nums[queue[0]]
```

始终就是当前窗口最大值。

### `<` 和 `<=`

这里维护单调队列时使用的是：

```
nums[queue[len(queue)-1]] < nums[right]
```

其实也可以写成：

```
nums[queue[len(queue)-1]] <= nums[right]
```

区别主要体现在出现相同数字时。

例如：

```
[3, 3]
```

如果使用 `<`，第一个 3 不会被删除：

```
[第一个3, 第二个3]
```

如果使用 `<=`，第二个 3 进入时会淘汰第一个 3：

```
[第二个3]
```

两种写法都可以正确求出窗口最大值。

### 时间复杂度

最终算法的时间复杂度是：O(n)

这里比较容易产生一个疑问，代码里明明存在嵌套循环：

```
for right := range nums {

  for len(queue) > 0 &&
    nums[queue[len(queue)-1]] < nums[right] {

    queue = queue[:len(queue)-1]
  }
}
```

为什么不是：O(n²)

关键在于：内层 `for` 并不是每一次都重新遍历整个队列。

对于每一个元素下标来说，它最多只会进入队列一次，然后未来要么从队尾被更大的元素淘汰一次要么：因为滑出窗口，从队首被删除，一个元素一旦被删除，就永远不会重新进入队列。

因此所有：

```go
queue = queue[:len(queue)-1]
```

操作加起来最多执行 O(n) 次。

所有：

```go
queue = append(queue, right)
```

也只执行 n 次。所以整个算法虽然看起来存在嵌套循环，但所有队列操作加起来仍然只有 O(n) 次。所以最终的时间复杂度为 O(n)

## Python 代码
```python
# 导入双端队列
from collections import deque

class Solution:
    def maxSlidingWindow(self, nums: List[int], k: int) -> List[int]:
        res = []
        queue = deque()

        for right in range(len(nums)):
            left = right - k + 1

            # 删除已滑出窗口的队首元素
            if len(queue) > 0 and queue[0] < left:
                queue.popleft()

            # 维护单调递减的队列
            while len(queue) > 0 and nums[queue[-1]] < nums[right]:
                queue.pop()

            # 当前下标入队
            queue.append(right)

            if right >= k - 1:
                res.append(nums[queue[0]])

        return res
```
