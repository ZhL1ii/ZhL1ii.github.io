滑动窗口是一类非常常见的双指针技巧。

如果窗口长度固定，比如长度始终为 `k`，那么窗口每向右移动一步，只需要让左边界和右边界同时向右移动。

而不定长滑动窗口则不一样。它的窗口大小会随着当前状态动态变化：

- `right` 负责不断扩大窗口；
- `left` 根据窗口当前是否符合要求，决定是否收缩窗口；
- 在合适的时机记录答案。

因此，不定长滑动窗口的关键在于：**什么情况下当前窗口是符合要求的？窗口符合要求或者不符合要求时，应该做什么？**

下面通过 LeetCode T3 和 T76 来理解这个过程。

------

## 一、[无重复字符的最长子串](https://leetcode.cn/problems/longest-substring-without-repeating-characters/)

题目要求：给定一个字符串 `s`，找出其中不含有重复字符的最长子串的**长度**。

例如：

```text
s = "abcabcbb"
```

的答案为：

```text
"abc"
```

长度为 `3`。

------

### 1、自然的窗口思路

我们可以维护一个窗口：

```text
[left, right]
```

其中 right 不断向右移动，把新的字符加入窗口。同时使用一个 `map` 记录窗口中每个字符出现的次数：

```go
window := make(map[byte]int)
```

当 `right` 指向一个新字符：

```go
ch := s[right]
window[ch]++
```

此时就出现了一个很关键的问题：当前窗口什么时候是不符合要求的？

T3 的要求是：**窗口中不能出现重复字符**，因此，如果当前加入的字符：

```go
window[ch] > 1
```

就说明当前窗口已经出现重复字符。此时该窗口就不符合要求。

------

### 2、窗口不符合要求时，收缩 left

例如：

```text
s = "abca"
```

当窗口扩展到：

```text
abca
^  ^
L  R
```

此时：

```go
window['a'] == 2
```

窗口中出现了重复的 `a`，此时开始移动 `left`。

每移动一次：

```go
window[s[left]]--
left++
```

直到：

```go
window[ch] <= 1
```

窗口重新变成符合要求的状态，因此代码可以写成：

```go
for right := 0; right < len(s); right++ {
	ch := s[right]

	window[ch]++

	for window[ch] > 1 {
		window[s[left]]--
		left++
	}
}
```

这里的 `for` 非常重要。

```go
for window[ch] > 1
```

因为我们不知道需要移动多少次 `left`，才能让窗口符合要求，所以需要用循环。

------

### 3、更新答案

当上面的 left 右移结束之后，当前窗口**一定满足没有重复字符的条件**，因此当前窗口就是一个正确的候选答案：

```go
ans = max(ans, right-left+1)
```

### 4、T3 完整代码

```go
func lengthOfLongestSubstring(s string) int {
	window := make(map[byte]int)

	left := 0
	ans := 0

	for right := 0; right < len(s); right++ {
		ch := s[right]

		window[ch]++

		for window[ch] > 1 {
			window[s[left]]--
			left++
		}

		ans = max(ans, right-left+1)
	}

	return ans
}
```

------

## 二、从 T3 理解不定长滑动窗口

T3 的代码其实可以抽象成一个非常典型的不定长滑动窗口结构：

```go
left := 0

for right := 0; right < len(s); right++ {
	// right 对应元素进入窗口

	for 窗口不符合要求 {
		// left 对应元素离开窗口
		left++
	}

	// 当前窗口符合要求
	// 更新答案
}
```

也就是：right 右移不断扩大窗口 → 当窗口不符合要求时，left 右移缩小窗口 → 窗口符合要求 → 记录答案

T3 要求的是：最长的符合要求的窗口，因此策略非常自然：**只要窗口不符合要求，就不断缩小；一旦符合，就尽可能保留当前的大窗口。**理解这一点以后，再看 T76，就会发现两道题虽然都使用滑动窗口，但是 `left` 的移动时机恰好相反。

## 三、T76：[最小覆盖子串](https://leetcode.cn/problems/minimum-window-substring/)

题目要求：给定两个字符串 `s` 和 `t`，返回 `s` 中包含 `t` 所有字符的最短子串。

例如：

```text
s = "ADOBECODEBANC"
t = "ABC"
```

答案：

```text
"BANC"
```

------

### 1、先从最自然的方法开始

刚开始做这道题时，可以暂时不要考虑最优解。先想一个最直接的问题：怎么判断当前窗口是否已经覆盖 `t`？

例如：

```text
t = "AABC"
```

说明窗口至少需要：

```text
A：2 个
B：1 个
C：1 个
```

因此可以准备两个 map。

第一个：

```go
need := make(map[byte]int)
```

记录 `t` 的需求。

第二个：

```go
window := make(map[byte]int)
```

记录当前窗口中的字符数量。

先统计 `t`：

```go
for i := range t {
	need[t[i]]++
}
```

例如：

```text
t = "AABC"
```

最终得到：

```text
need['A'] = 2
need['B'] = 1
need['C'] = 1
```

------

### 2、right 继续负责扩大窗口

和 T3 一样，我们让：right 不断向右移动：

```go
for right := 0; right < len(s); right++ {
	ch := s[right]
	window[ch]++
}
```

接下来要判断：当前窗口是否已经覆盖 `t`？

最直接的方法，就是遍历 `need`：

```go
flag := true

for k, v := range need {
	if window[k] < v {
		flag = false
		break
	}
}
```

注意这里的：

```go
window[k] < v
```

因为窗口中允许字符数量超过需求。

例如：

```text
t = "ABC"
```

而当前窗口：

```text
"AABC"
```

仍然完全覆盖 `"ABC"`。

所以真正的要求是：

```text
window[k] >= need[k]
```

只要某个字符：

```text
window[k] < need[k]
```

才说明窗口还不符合要求。

------

### 3、T76 和 T3 最大的区别

假设当前窗口已经覆盖 `t`。

例如：

```text
ADOBEC
```

已经包含：

```text
A B C
```

此时我们应该做什么？

T3 中，因为要求的是**最长**，意味着尽量保留最大窗口。

但 T76 恰好相反，要求**最短**，因此，**只要当前窗口符合要求，就应该立刻尝试移动 left，把窗口缩小。**

所以 T76 的结构是：

```go
for flag {
	// 当前窗口是符合要求的

	// 删除最左边字符
	window[s[left]]--
	left++

	// 再判断窗口是否符合要求
}
```

这也是 T3 与 T76 最值得放在一起理解的地方。

T3：窗口不符合要求 → 缩

T76：窗口符合要求 → 缩

------

### 4、初始思路的完整代码

因为题目要求最短窗口，所以只需要记录：

```go
start := 0
minLen := len(s) + 1
```

每当窗口符合要求时：

```go
if right-left+1 < minLen {
	start = left
	minLen = right - left + 1
}
```

然后继续移动 `left`。

第一版代码如下：

```go
func minWindow(s string, t string) string {
	need := make(map[byte]int)
	window := make(map[byte]int)

	for i := range t {
		need[t[i]]++
	}

	left := 0

	start := 0
	minLen := len(s) + 1

	for right := 0; right < len(s); right++ {
		ch := s[right]
		window[ch]++

		flag := true

		// 判断当前窗口是否已经覆盖 t
		for k, v := range need {
			if window[k] < v {
				flag = false
				break
			}
		}

		// 当前窗口符合要求，尝试不断缩小
		for flag {
			if right-left+1 < minLen {
				start = left
				minLen = right - left + 1
			}

			window[s[left]]--
			left++

			// 窗口缩小以后重新判断
			flag = true

			for k, v := range need {
				if window[k] < v {
					flag = false
					break
				}
			}
		}
	}

	if minLen == len(s)+1 {
		return ""
	}

	return s[start : start+minLen]
}
```

这一版的好处是：思维过程非常自然，基本就是把我们脑中的逻辑直接翻译成了代码：

接下来再考虑：哪里存在可以优化的点？

------

### 5、第一步优化：不再重复遍历 need

观察第一版代码，会发现一个明显的问题：

```go
for k, v := range need {
	if window[k] < v {
		...
	}
}
```

这个判断执行得非常频繁。每移动一次 `right`，需要遍历 `need`。每移动一次 `left`，又要重新遍历 `need`。

但仔细想一下：当一个字符进入或者离开窗口时，真正发生变化的其实只有这一个字符。

例如当前加入的是：`A`

那么：`B C D ...`

这些字符的状态根本没有变化。既然只有一个字符变化，为什么还要把整个 `need` 重新扫描一遍？

因此可以用一个变量用来记录当前已经满足要求的字符种类数，例如：

```go
valid := 0
```

示例：

```text
t = "AABC"
```

那么：

```text
need[A] = 2
need[B] = 1
need[C] = 1
```

一共需要满足 3 种字符。

假设当前窗口：`A = 2 B = 1 C = 0`，那么：valid = 2，因为 A 满足了、B 满足了、C 不满足

如果之后 C 进入窗口：`C = 1`，那么此时 valid = 3

同时：

```go
valid == len(need)
```

就说明窗口已经覆盖 `t`。

------

### 6、如何维护 valid

#### 当字符进入窗口时

假设：

```text
need[A] = 2
```

当第一个 A 进入窗口：

```text
window[A] = 1
```

还没满足要求，因此 `valid` 不变。第二个 A 进入：

```text
window[A] = 2
```

此时：

```go
window[A] == need[A]
```

A 从不满足变成了满足，因此需要 valid++

代码如下：

```go
if _, ok := need[ch]; ok {
	window[ch]++

	if window[ch] == need[ch] {
		valid++
	}
}
```

这里：

```go
if _, ok := need[ch]; ok
```

是为了判断当前字符是不是 `t` 真正需要的字符？

例如：

```text
s = "ADOBEC..."
t = "ABC"
```

其中：

```text
D O E
```

都不属于 `t`。

这些字符虽然会影响窗口长度，但没必要记录进 `window`。

因此只维护 `A B C`即可。

#### 当字符离开窗口时

假设：

```text
need[A] = 2
window[A] = 2
```

说明 A 当前刚好满足要求，而现在 `left` 要删除一个 A，删除之后：

```text
window[A] = 1
```

A 就会从满足变成不满足，就需要 valid--

因此代码应该是：

```go
if window[ch] == need[ch] {
	valid--
}

window[ch]--
```

注意顺序！必须先判断：

```go
window[ch] == need[ch]
```

再：

```go
window[ch]--
```

因为我们判断的是删除这个字符以前，它是否处于**刚好满足需求**的状态。

------

### 7、使用 valid 后的版本

有了：

```go
valid
```

以后，之前复杂的：

```go
flag := true

for k, v := range need {
	if window[k] < v {
		flag = false
		break
	}
}
```

可以完全删除，当前窗口是否符合要求，只需要：

```go
valid == len(need)
```

因此代码变成：

```go
func minWindow(s string, t string) string {
	need := make(map[byte]int)
	window := make(map[byte]int)

	for i := range t {
		need[t[i]]++
	}

	left := 0

	start := 0
	minLen := len(s) + 1

	valid := 0

	for right := 0; right < len(s); right++ {
		ch := s[right]

		if _, ok := need[ch]; ok {
			window[ch]++

			if window[ch] == need[ch] {
				valid++
			}
		}

		for valid == len(need) {
			if right-left+1 < minLen {
				start = left
				minLen = right - left + 1
			}

			ch := s[left]

			if _, ok := need[ch]; ok {
				if window[ch] == need[ch] {
					valid--
				}

				window[ch]--
			}

			left++
		}
	}

	if minLen == len(s)+1 {
		return ""
	}

	return s[start : start+minLen]
}
```

这一层优化体现了一个非常常见的思想：**如果一个状态可以随着数据变化增量维护，就没必要每次重新计算。**

------

### 8、进一步优化：map 改为数组

到这里，算法复杂度其实已经很好了。因为字符串中的每个位置：最多被 right 访问一次 / 最多被 left 访问一次，因此整体时间复杂度已经是：`O(|s| + |t|)`，接下来的优化主要就是常数优化。

题目中的字符属于英文字母，因此完全可以用固定长度数组代替：`map[byte]int`

例如：

```go
var need [128]int
var window [128]int
```

字符本身就是一个 byte，可以直接作为数组下标。

例如：

```text
'A' 的 ASCII 值为 65
```

所以：

```go
need['A']
```

本质就是访问：

```go
need[65]
```

相比 map，数组访问不需要哈希计算，因此会更轻量。

------

### 9、统计不同字符的数量

原来我们通过 `len(need)` 来计算 `t` 中一共有多少种字符。换成数组以后，`len(need)`永远都是 `128`，显然已经不能表示字符种类数。因此需要自己维护一个变量用于统计 t 中的不同字符的数量。

```go
required := 0
```

代码：

```go
for i := range t {
	if need[t[i]] == 0 {
		required++
	}

	need[t[i]]++
}
```

例如：

```text
t = "AABC"
```

第一个 A：

```text
need[A] == 0
required++
```

第二个 A：

```text
need[A] != 0
```

因此不增加。

最终：

```text
required = 3
```

分别对应：

```text
A B C
```

------

### 10、最终版本

最终可以得到：

```go
func minWindow(s string, t string) string {
	var need [128]int
	var window [128]int

	required := 0

	for i := range t {
		if need[t[i]] == 0 {
			required++
		}

		need[t[i]]++
	}

	valid := 0

	left := 0
	start := 0
	minLen := len(s) + 1

	for right := 0; right < len(s); right++ {
		ch := s[right]

		if need[ch] > 0 {
			window[ch]++

			if window[ch] == need[ch] {
				valid++
			}
		}

		// 当前窗口已经覆盖 t
		// 尝试继续缩小窗口
		for valid == required {
			if right-left+1 < minLen {
				start = left
				minLen = right - left + 1
			}

			ch := s[left]

			if need[ch] > 0 {
				if window[ch] == need[ch] {
					valid--
				}

				window[ch]--
			}

			left++
		}
	}

	if minLen == len(s)+1 {
		return ""
	}

	return s[start : start+minLen]
}
```

这已经是一版时间复杂度和实现都比较理想的写法。

## 四、不定长滑动窗口的通用思路

通过 T3 和 T76，可以发现不定长滑动窗口虽然题目形式不同，但核心始终围绕三个动作：

- right 扩大窗口
- left 收缩窗口
- 记录答案

### 1. 窗口需要维护的状态

首先要明确：当前窗口中，需要记录哪些信息才能判断窗口是否符合要求。

例如 T3 中，需要知道每个字符出现了多少次：

```go
window[ch]
```

因为：

```go
window[ch] > 1
```

就意味着窗口中出现了重复字符。

而 T76 中，需要同时知道：

```text
need  ：目标字符串需要哪些字符以及数量
window ：当前窗口拥有多少这些字符
```

进一步还可以用：`valid`记录当前已经满足要求的字符种类数。

---

### 2. 窗口符合要求的条件

这是滑动窗口中最重要的问题。

- T3 ：窗口内没有重复字符，就是符合要求的。

- T76 ：窗口已经覆盖 t 中所有字符，就是符合要求的。

只有先定义清楚什么样的窗口符合要求，才能决定 `left` 应该什么时候移动。

---

### 3. left 移动的时机

T3 和 T76 最值得放在一起理解的地方，就是它们的移动时机恰好相反。

#### 求最长窗口

例如 T3，我们的目标是让窗口在符合要求的前提下尽可能大。

因此：当窗口符合要求，就尽量保留，不主动缩小，而当窗口不符合要求了，就移动 left，直到窗口重新符合要求。

对应模板：

```go
left := 0

for right := 0; right < n; right++ {
	// right 对应元素进入窗口

	for 窗口不合法 {
		// left 对应元素离开窗口
		left++
	}

	// 此时窗口合法
	// 更新最长答案
}
```

---

#### 求最短窗口

与上面的求最长窗口恰好相反。

```go
left := 0

for right := 0; right < n; right++ {
	// right 对应元素进入窗口

	for 窗口合法 {
		// 当前窗口是一个候选答案
		// 更新最短答案

		// left 对应元素离开窗口
		left++
	}
}
```

---

### 4. 更新答案的时机

这一点也和 `left` 的移动时机有关。

对于 T3：收缩结束 → 当前窗口符合要求 → 更新最长答案

因此：

```go
for 窗口不符合要求 {
	left++
}

ans = max(ans, right-left+1)
```

而对于 T76：当前窗口符合要求 → 它就是一个候选答案 → 先记录 → 再继续缩小

因此：

```go
for 窗口符合要求 {
	ans = min(ans, right-left+1)

	left++
}
```

---
